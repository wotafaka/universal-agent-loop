# Universal Agent Loop — package development

This workspace maintains the provider-neutral Universal Agent Loop starter by Вадим Захаров.
Read README.md and docs/STATUS.md before changing it. The source project is read-only;
do not change its active task, launch its providers, or run its lifecycle tools.

- Follow the owner's current task. Preparation is not permission to publish.
- Preserve the byte-exact reference/ snapshot and its manifest; adapt elsewhere.
- Keep roles separate from model names. No provider is required by the starter.
- An owner's explicit engineer/model choice is binding for local development. Do not
  substitute an internal agent merely because it has a separate context; verify the
  selected external route and report an unavailable route honestly. This local choice
  does not impose that provider on users of the portable templates.
- Distinguish guidance, executable reference checks, and deployed automation.
- Use the smallest verifiable change; preserve safety, evidence and ownership.
- New executable behavior needs a reproducing check and a separate implementation
  session when the owner requests independent engineering. Copying verified assets
  and authoring documentation do not establish a new implementation runtime.
- Load skills only when triggered; skill instructions do not grant permissions.
- Use one writer per checkout. Reviewers do not change the candidate they review.
- No secrets, personal profiles, machine-specific paths or raw private reports.
- No paid model calls, dependency installs, Git initialization or publication merely
  to prepare this package. Ask only when new authority is genuinely required.
- Manual owner acceptance is the portable default. A review PASS is not acceptance.
- Never claim all source infrastructure has been ported while STATUS lists gaps.
