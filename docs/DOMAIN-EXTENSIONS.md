# Optional domain packs

Core workflow should not load domain constraints for unrelated tasks. Domain packs are
additional requirements, not permission to access data or perform privileged operations.

The source's research-integrity and walk-forward skills contribute these preserved
requirements for a future empirical-evaluation pack: freeze hypothesis, semantics, inputs,
baseline and metrics before evaluation; distinguish event/availability/revision time;
prevent future-data leakage; separate provisional labels from verified truth; group
dependent samples across splits; preserve untouched evaluation data; disclose repeated
tuning, missingness, negative results and selection bias. A retrospective result is not
evidence the inputs were available at the decision time. A proxy metric is not user value.

Source-specific station, settlement, market/capital gates and financial cost metrics
are intentionally not generalized into arbitrary application rules. Their original
skills remain source anchors in TRANSFER/SOURCE_SNAPSHOT; adopting a financial project
requires a separately reviewed domain pack, not deleting those safeguards.

For credentials, payments, signing or irreversible operations, require exact owner scope,
least privilege, secret storage outside prompts/repository/logs, redaction before capture,
task-bound limits and independent review. Ambiguous remote outcomes must be reconciled
before repetition; do not retry a possibly completed charge/order. Live activation needs
a deliberate fresh authorization boundary; a passing simulation never arms production.

This page preserves design obligations only. It is not a deployed payment/trading safety
system or a substitute for the target project's domain rules. The portable starter
performs no authenticated request, trading action or deployment.
