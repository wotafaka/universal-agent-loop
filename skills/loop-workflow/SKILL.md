# Loop workflow

Locate the project's entrypoint, current task and state. Read the complete task,
small binding rules and triggered skills. Resolve contradictions against raw evidence
and the authoritative originals, not chat recollection. Do not create a replacement
active task when another writer owns the project.

Record your role, permitted files, checks and acceptance boundary. Engineer, observer
and reviewer are different roles even when they use the same model. Do not pass an
entire previous conversation when a task-bound handoff suffices.

Use a supplied repair pack only after its actual verification succeeds. If the project's
startup mutates pack-bound state, follow its documented verify-first exception instead.
An observer is a continuation of parent startup: it reads supplied instructions/evidence
only and never runs project lifecycle commands.

Before handoff, name candidate identity, raw checks, unresolved findings, skill application
and next action. Distinguish implemented, tested, reviewed and accepted. Update compact
current state; preserve old evidence and material lessons. No acceptance by the implementer.
