# Настоящий пример: Lineclean

Это результат небольшой задачи, которую действительно выполнил отдельный инженер,
проверил отдельный ревьюер и принял владелец. Не демонстрация с выдуманными ответами AI.

Утилита удаляет повторяющиеся строки, сохраняя порядок, регистр и пробелы.
Зависимостей, ключей API и подписок для запуска готового результата не нужно — только Python.

## Попробовать за несколько минут

Откройте терминал в этой папке и выполните:

```text
python -I -S -B lineclean.py examples/input.txt
python -I -S -B -m unittest discover -s tests -v
```

Первая команда печатает очищенный список, не меняя исходный файл:

```text
pear
apple

Яблоко
 apple
```

Перед последним `apple` остаётся пробел: это другая строка. Вторая команда должна
завершиться `Ran 17 tests` и `OK`; длительность зависит от компьютера.
Это запуск готовой программы и её проверок, не повторный вызов инженера или аудитора.

## Как прошла работа

| Шаг | Что произошло | Где посмотреть |
|---|---|---|
| Задание | Определили правила строк, ошибки ввода и границы установки | [TASK](TASK.md), полный исторический контракт в `history/task.txt` |
| Инженер | Написал тесты, увидел падение на заглушке, реализовал программу | `lineclean.py`, `tests/test_lineclean.py`, `history/engineer-events.json` |
| Проверки | Исправил два неверных ожидания тестов по исходному требованию; получил 17 успешных тестов | `history/implementation.txt`, `history/parent-tests.txt` |
| Независимое ревью | Нашло ложное утверждение «код не менялся между RED и GREEN» | `history/review-initial.txt` |
| Исправление | Исправили отчёт, задачу и память; работающий код не переписывали | `history/implementation.txt`, `history/review-final.txt` |
| Приёмка | Владелец принял проверенный результат после ревью | `history/owner-acceptance.txt` |

**Было:** отчёт неверно описывал историю изменения кода. **Стало:** ревьюер сопоставил
его с журналом; отчёт исправили, сохранив неудачные проверки. Это конкретный результат
пилота, а не доказательство, что отдельный ревьюер всегда находит больше ошибок.

В пилоте инженер и ревьюер использовали разные инструменты. Можно повторить роли
в одном инструменте, но в отдельных сессиях: [готовые задания](REPRODUCE.md).
Отдельный контекст не требует отдельной подписки, если ваш инструмент предоставляет
такую возможность; доступность этой функции проверяется в вашем окружении.

## Что сохранено и что изменено

Код, тесты и входной файл скопированы побайтово из принятого пилота. В исторических
документах и выборке событий заменены приватные пути и идентификатор сессии.
[PROVENANCE](PROVENANCE.json) перечисляет исходные и опубликованные хэши и преобразования.
Документы `history/` — записи прошлого, не действующие инструкции: оставшиеся относительные
пути описывают тогдашнюю установку и не обещают наличие всего её содержимого здесь.
Состояние «ожидает ревью» в отчёте инженера предшествует последующей приёмке, не противоречит ей.

Проверенный тогда режим — Windows, отдельный внешний инженер и Sol-ревьюер.
Полные приватные журналы не опубликованы; выборка не является независимо подписанным
протоколом. Этот пример не доказывает автоматизацию нового runtime, экономию токенов
или сравнительное преимущество моделей. Тест с именем `test_cli_output_is_idempotent`
проверяет повторяемость; настоящая идемпотентность отдельно проверяется на функции.
